# Contributing to CivilTools

We love your input! We want to make contributing as easy and transparent as possible, whether it's:

- Reporting a bug
- Discussing the current state of code
- Submitting a fix
- Proposing new features
- Becoming a maintainer

## Development Process

We use GitHub to host code, to track issues and feature requests, as well as accept pull requests.

1. Fork the repo and create your branch from `main`.
2. If you've added code that should be tested, add tests.
3. If you've changed APIs, update the documentation.
4. Ensure the test suite passes.
5. Make sure your code lints.
6. Issue that pull request!

## Pull Request Process

1. Update the README.md with details of changes if applicable.
2. Update the CHANGELOG.md with a description of your changes.
3. The PR will be merged once you have the sign-off of maintainers.

## Report bugs using GitHub's [issue tracker](../../issues)

We use GitHub issues to track public bugs. Report a bug by [opening a new issue](../../issues/new/choose).

## Write bug reports with detail, background, and sample code

**Great Bug Reports** tend to have:

- A quick summary and/or background
- Steps to reproduce (be specific: what did you do, what happened, what did you expect?)
- Code samples if relevant
- What environment (OS, browser, Node version, etc.)
- Additional context

## Use a Consistent Coding Style

- 2 spaces for indentation (no tabs)
- Single quotes for strings
- Trailing commas where valid
- 100 character print width
- Run `npm run format` or `npx prettier --write .` to format
